# 自分専用の「AI 会議パートナー」を作る（1）計画と、Google Meet の字幕を読み取る検証

Google Meet の会議に「参加者の 1 人」として入って、会話を聞きながら要約や議事録を作ってくれる AI を、自分用に作り始めました。

この連載では、その開発の過程を順番に書いていきます。1 回目の今回は、何を作ろうとしているのかと、最初の検証（Phase 0）でわかったことをまとめます。

---

## 作りたいもの

自分の Google Meet に参加者として入り、会話を聞きながら次のことをしてくれる「会議パートナー」です。

1. **リアルタイム要約**: 会議中、約 1 分ごとに要約を更新して、手元の画面に表示する
2. **資料化**: 会議が終わったら、議事録・決定事項・ToDo を Google ドキュメントにまとめる
3. **会話への参加**: 「パートナー、今の論点をまとめて」と呼びかけたら、チャットで答える

最終的には、2D のアバター（映像と音声）として発言できるところまで作りたいと考えています。

使うのは自分だけで、自分が主催する会議の中だけで動かす前提です。

## なぜ「ブラウザを操作するボット」を自作するのか

最初に、公式の仕組みで作れないかを調べました。

- 会議の音声や映像をリアルタイムに受け取れる公式 API（Meet Media API）は、2027 年 1 月に提供を終える予定だと告知されています。
- 会議の情報を扱う別の公式 API はありますが、会議中のチャットに投稿する方法は見当たりませんでした。

そこで、**普通の Chrome をプログラムから操作して、ボット用のアカウントで会議に参加させる**方法を選びました。会話の内容は、Meet の自動字幕を画面から読み取ります。

ブラウザの自動操作は、ブロックされたり、Meet の画面が変わると動かなくなったりする弱点があります。それを承知の上で、まずは「本当にできるのか」を確かめるところから始めました。

## 全体の構成

```
自宅の PC
 ├─ Chrome（ボット用アカウントでログイン済み。プログラムから操作）
 │    ├─ 字幕を読み取る → 発言として確定する
 │    ├─ チャットを読む・投稿する
 │    └─ （将来）アバターの映像と音声を流す
 ├─ 本体のプログラム（TypeScript）
 │    ├─ 確定した発言のログ（話者・時刻・内容）
 │    ├─ 約 1 分ごとに Claude で要約
 │    └─ 会議の終わりに議事録を清書して Google ドキュメントへ
 └─ 手元の画面（要約・決定事項・ToDo をリアルタイム表示）
```

開発は 4 段階で進めます。

| 段階 | 内容 |
|---|---|
| Phase 0 | 実機での検証（参加できるか、字幕を読めるか、負荷はどうか など） |
| Phase 1 | 聞く・まとめる（字幕 → 要約を画面に表示、終了時に議事録を作成） |
| Phase 2 | チャットで会話に参加する |
| Phase 3 | 2D アバターとして話す |

開発には、AI のコーディングアシスタント（Claude Code）を使っています。私が方針を決めてテスト会議を用意し、スクリプトの作成や実行、ログの解析は AI に任せる、という分担です。

## Phase 0：やってみてわかったこと

Windows 11 の自宅 PC で、Node.js と TypeScript、ブラウザ操作ライブラリの Playwright を使って検証しました。テスト用の会議を何度か開き、ボットを参加させて、字幕の動きを記録しました。

### 1. Google のログインで、いきなりつまずいた

プログラムから操作している Chrome で Google にログインしようとすると、「このブラウザまたはアプリは安全でない可能性があります」と表示されて拒否されました。

そこで、**ログインだけは普通に起動した Chrome で手動で行い**、そのログイン状態を保存したものを、プログラムから操作する Chrome で使うことにしました。この方法だと、Meet への参加は問題なくできました。

### 2. 字幕の「中身」をどう調べたか

Meet の画面がどういう作りになっているかは、公開されていません。そこで、最初は字幕の場所を決め打ちせず、**画面の中で文字が変わった部分を全部記録**し、後から「どれが字幕か」を探す方法をとりました。

その結果、字幕は「字幕」という名前の付いた領域の中に、**話している人ごとのブロック**として並んでいることがわかりました。各ブロックには、話者の名前と、話している内容が入っています。

### 3. 字幕は、話している間ずっと書き換わる

自動字幕は、話している最中に何度も書き直されます。たとえば、こんな具合です。

```
今。
→ スター！
→ スターダムを見てます。
```

このまま全部を記録すると、同じ発言が何度も重複してしまいます。どの時点で「この発言は確定した」と判断するかが、このプロジェクトの最初の山場でした。

記録を解析してわかったのは、次の点です。

- 字幕の文は「。」「？」のあとに**半角スペース**を入れて区切られている
- 書き換わるのは、いつも**最後の区間（最後の「句読点＋スペース」より後ろ）だけ**。3 回の録画、合計 880 回の書き換えで、それより前が変わったことは一度もなかった
- ただし、最後の区間が**丸ごと消える**ことがある。いちばん遅いケースでは、最後の更新から 5.5 秒後に消えた

計画の段階では「2 秒更新がなければ確定」と考えていましたが、これでは足りないことがわかりました。そこで、確定のルールを次のように決めました。

- 最後の区間より前は、次の区間が始まった時点で確定する
- 最後の区間は、6〜8 秒更新がなければ確定する

話してから字幕が出るまでの遅れは、体感で 1 秒もありませんでした。ただ、確定を待つぶん、要約に使えるのは話してから 6〜8 秒後になります。

### 4. 実際に動かすまでわからない「落とし穴」

ほかにも、実際に動かして初めて気付いたことがたくさんありました。

- **字幕の部品は使い回される**: 画面から消えた字幕のブロックが、十数分後に別の発言の入れ物として再利用されていた
- **同じ発言が 2 回出る**: 同じ部屋にある 2 台の端末が同じ声を拾うと、同じ文が別々のブロックに、ほぼ同時に表示された
- **ボタンの名前が想定と違う**: マイクのボタンにマウスを乗せると「マイクをオフにする（Ctrl+D キー）」と出るが、プログラムから見たボタン名は「マイクをオフ」だった
- **思わぬポップアップ**: マイクをオフにした直後に「デスクトップ通知を受け取る」という案内が出て、参加ボタンを押せなくなった
- **終了画面の文言**: 主催者が会議を終えると、ボットの画面には「主催者が会議を終了して全員を退出させました」と表示された

どれも、ボットが自分でマイクとカメラをオフにして参加し、会議が終わったら自動で止まるように直しました。

### 5. 無料アカウントの「60 分の壁」

90 分のテストをしたところ、開始から約 66 分で会議が終了してしまいました。

無料の個人アカウントでは、**3 人以上の会議は 60 分まで**という制限があります。ボットも参加者に数えられるので、**2 人の会議にボットを入れると 3 人になり、60 分で切れてしまいます**。長い会議で使うには、有料のプランが必要になりそうです。

### 6. パソコンへの負荷

ボット用の Chrome のメモリ使用量は、約 900MB で安定していました（66 分まで計測）。少なくとも 1 時間程度なら、増え続けることはなさそうです。

### 7. 要約の試作

最後に、確定した発言のログを Claude に渡して、要約・決定事項・ToDo・未解決論点を作らせてみました。

テスト用の雑談 20 分ぶんで、かかった時間は約 14 秒、費用は約 0.04 ドル（6 円ほど）でした。

うれしかったのは、次の 2 点です。

- 雑談しかしていない会議で、**決定事項や ToDo を作り出さず、「なし」と答えた**
- 字幕の誤変換を、前後の言い直しから推定して指摘した（「生涯乱闘」→「場外乱闘」、「ダウンロードを使って」→「タオルを使って」など）

## 今の状況と、次にやること

Phase 0 で、「ボットとして参加して、字幕を読み取り、発言として確定させ、要約する」ところまでは動くことを確認できました。

次は、**専門用語を含む本物の打ち合わせ**で録画して、字幕から作った要約に致命的な誤りがないかを確かめます。これが合格すれば、Phase 1（会議中のリアルタイム要約と、Google ドキュメントへの議事録出力）に進みます。もし字幕の精度が足りなければ、音声を直接文字起こしする方法も比べてみるつもりです。

## 気を付けていること

- 使うのは自分だけで、**自分が主催する会議の中だけ**で動かします
- 会議の参加者には、録画して要約に使うことを事前に伝えます
- ブラウザの自動操作は、Google の利用規約上グレーになりうるため、ボット用のアカウントはメインのアカウントと分けています
- 会議の発言内容やログイン情報、API キーは、コードの保管場所（リポジトリ）には入れていません

次回は、本物の打ち合わせで試した結果を書く予定です。
